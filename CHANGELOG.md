## [Unreleased]

Settings › Catalogue reads the distinct categories in use, not every item.

The CI workflow stays hand-kept. See docs/ADOPTION_DECISIONS.md, 2026-10-08.

- Abatty 0.4.0 → 0.6.0: the hooks and harness brought to 0.6.0 (`abatty update`); the redefined `docs.behindCode` floor re-recorded (`abatty baseline`, every floor unchanged, three new metrics at 0); every browser spec now takes `test` from `e2e/fixtures.ts`, which fails a test whose page throws or does not hydrate (TEST-E2E-ERRORS). ### Added

- Quotations — a destination is quoted for a number of containers (legacy routeQty): a line marked "per container" (the default, a catalogue line included) is multiplied by it, a line unticked counts once — the legacy `routeUnit × routeQty + routeBoxSell`; the title says "× 3" and each line what it is multiplied by. A free-time line is a term, not a charge: named on the paper ("— terms"), never totalled, never billed (legacy free-time conditions). A catalogue free-time item says whether it is demurrage, detention or combined, and at origin or destination, and the destination's starter lines read that instead of the item's name. An accepted destination opens its booking with as many boxes as were quoted. The billing and the cost tabs count the same. Migration 0025 (existing lines were all whole-destination lines: they are marked per container; existing free-time lines become terms).
- Bookings — a Cost & margin tab (legacy, `costs.view`): the cost expected from the quotation's destination (its buy side, line by line — change a price there and this follows), the supplier bills recorded against the booking with the variance against the expected ("+ €120.00 over", "− €40.00 under", "matches"), and the profit and margin on the expected cost and on the bills received. Opening the figures is written to the audit log (legacy ACCESS_WATCH, first of its kind here).
- Bookings — a Tracking tab (legacy track tab): where the shipment stands for the consignee (release states: not released, three holds, telex, released — a hold says who asked and what must happen, opens a task for tomorrow to clear it and shows red in the header; lifting it closes the task), how the original papers travel (who receives them, courier, date, waybill, with the courier's own tracking page when it has one; shown for the paper document types), and the journey's milestones ticked by hand with the day each was done, the current one marked. Settings › Release & tracking edits the three tables (the legacy six states, seven couriers, eight steps by default); the paper document types are a list in Settings › Lists. Migration 0024.
- Bookings — the goods of a box (legacy HS lines): weight and packages per HS code, one line each, the box totals following as they are typed and becoming the box's cargo weight and packages — so the B/L, the VGM and the customs declaration read the same numbers; what the shipper declared (packages, package type) when there are no lines; the B/L description printed word for word. Settings › HS codes (the 45 legacy codes by default) and the package types list (Settings › Lists, the 20 legacy types). The papers print each line with its description. Migration 0023.
- Bookings — loading per box (legacy per-box loading card, BUILD_PLAN 1.10): each container carries its own loading address, date and hour, loading mode, trucker, extra stops (one per line) and, for a box left on site, when the truck comes back for it. Nothing is inherited between boxes: the booking's own details stand in for a one-box booking only, so two drivers are never sent to one address at one hour. The trucker copy prints each box's loading, stops and pick-up, and says "Not ready to go out — missing: …" while a detail is lacking; the booking page says the same next to each copy. The loading modes are a Settings table (Settings › Loading modes: name, hours included, direct or drop, surcharge catalogue item, quantity; the twelve legacy modes by default) and a quotation's destination carries the mode agreed, with what it means for the price under the field; an accepted destination hands its mode to the booking. Migration 0022.
- Installable app (PWA): a web manifest with the office's icon at every size (home screen, iOS, maskable), the theme colour in both schemes, and a small service worker — a navigation is always fetched live and never stored (every screen is personal); when the network is away it shows the new /offline page; the build's static files, the icons and the fonts are served from the cache once seen; server actions, React Server Component payloads, /api (the event stream, the downloads), the printed documents and the UBL files are never touched. Registered in production only; the proxy lets the manifest, the icons, the worker and /offline through without a session. A browser spec checks all of it.
- Accessibility: table header cells carry `scope="col"` and every table has a name; card titles are headings (h2) so a reader can walk the page by section; links that open a new tab say so (icon plus text for readers) and carry `rel="noopener"`; the month calendar is a labelled navigation of day links with the overdue count in words and the selected day as `aria-current`, in place of a half-built ARIA grid; every dialog has a description; the search box reports when it is busy; the chat list announces new messages only; a booking, a contact and a quotation page carry their reference as the page title (WCAG 2.4.2); the document declares both colour schemes.
- Forms check themselves in the browser before they reach the server, with the very zod schema the server action parses (58 forms: contacts, bookings, containers, files, quotations, catalogue, agreements, vessels, tasks, covers, messages, invoices, bills, payments, bank, VAT, assets, accruals, people, lists, rules, holidays): a missing field or a bad date is said at once, with the server's own words, and the server still parses every submission. Every field's control now names the text that describes it (its error, else its hint) and says when it is invalid, so a screen reader announces the message with the field (WCAG 3.3.1, 1.3.1). A refusal's toast stays eight seconds instead of four.

### Fixed

- Bookings — adding, editing or removing a container now re-plans the booking's document steps in the same transaction: the per-box steps (Certiweight) and the VGM wait follow the boxes and their weights, where before they went stale until another change touched the booking.
- Bookings — filing or refiling a document writes the file record, the step it settles (and the re-plan that follows) and the audit line in one transaction; a failure midway no longer leaves a file without its step, or a step without its audit line.
- Cache — a sailing moved, a booking put on a sailing, the cut-off offsets saved, a contact renamed, a task created or moved and the rule book re-planned now drop the cached bookings and quotations lists and the home panel that show those dates, names and counts; a quotation edit no longer flushes the bookings list (it shows no quotation data) but the home panel's value.
- Cache — invalidation is one atomic Redis script per call (every key of the tags, the tag sets, one round trip) instead of three round trips per tag; a value computed while a write landed is returned but no longer kept for its whole TTL (each tag carries a generation the read compares before storing).
- Bank auto-match reads the open invoices once and reduces them as lines are booked, instead of re-reading every issued invoice per bank line.

### Fixed

- Browser tests failed now and then by typing into a page before React had hydrated it: hydration then rewrote the field with the server's text (a textarea got it appended, a list gained a duplicate). Every spec now navigates through `open()`, which waits for the page's controls to hydrate (`HydrationMark`, and each control's React fiber behind the office's loading boundary); verified against the production build.
- The quotation editor browser test hard-coded a destination total, which broke when an earlier run had left a document for the same random country code (one of 9); it now compares the total before and after, and draws the code from 676.
- Saving a document rule or a holiday re-planned every live booking one at a time (a few queries and inserts each), about 30 s at 400 bookings and growing with every booking the office keeps. The bookings, their steps and what their quotations sold are now read in three queries and the new steps and audit lines written in batches; the outcome is the same.
- Invoicing a booking from its quotation also offered lines taken off the quotation and lines of declined destinations; it now offers only the live lines of the booking's own destination.
- The Activity browser test failed once a task in the database went overdue: its "Due" field locator also matched the "Overdue" section. It now matches the label exactly.
- Postgres and Redis stayed down after Docker Desktop restarted, and login failed with ECONNREFUSED: both services now restart with Docker (`restart: unless-stopped`).
- The live-updates stream threw "Controller is already closed" (an uncaught exception on the server) when a browser left while a message was on its way: the stream now stops once, whatever ends it first, and writes nothing after.
- The Journal drew a whole year at once and took 6–15 s to open; it now shows 100 entries a page, opening on the latest (the account ledger 200 lines a page, searchable too, each line keeping its true running balance), and can be searched by number, partner or label. Other long lists are bounded the same way: Contacts 100 a page, and each Activity bucket draws its first 50 tasks with the count of the rest.
- A new contact could stay missing from the customer and supplier pickers for up to five minutes: a shorter-lived cached list sharing the `contacts` tag shortened the tag's life below the pickers' key, so creating a contact no longer cleared it. A tag set's expiry now only ever rises.
- A bank line's de-duplication key now includes the payer's name: two payers sending the same amount with the same note on the same day were taken for one.
- Forms lost everything typed after a validation error (React 19 resets `<form action>` once the action returns); all stateful forms now submit through `ActionForm`.
- Success toasts never appeared when the action removed its own component (archive, cancel, remove container); toasts now fire when the result arrives (`useToastedAction`).
- Emptying an optional field (contact phone, booking vessel…) did not clear it, because Drizzle skips `undefined`; updates now send null (`nullMissing`).
- CI ran the opt-in scrub scan that abatty.config.json disables, failing every push; the step is removed.
- The generated CI workflow had an invalid YAML line (bypass-rate step), now a block scalar.
